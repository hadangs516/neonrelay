# NEON RELAY — 마지막 신호

오리지널 3D 아레나 생존 액션. 작은 배달 로봇 루프가 멈춘 공중 도시의 신호기 3개를 복구하고, 최종 감시자를 정지시키는 6분짜리 게임입니다.

**출시 후보 v1.0입니다. 모의 로직 테스트를 통과했으며, 실제 Google 배포 연결과 휴대폰 화면 확인은 아직 필요합니다.**

## 1. Apps Script 설정 — 먼저 진행

1. 기록용 구글 시트에서 **확장 프로그램 → Apps Script**를 엽니다.
2. 기존 임시 코드를 `Code.gs`의 내용으로 교체하고 저장합니다. 다른 파일에 중복된 `doGet`, `doPost`, `setup` 함수가 있으면 제거하세요.
3. 상단 함수 선택에서 **setup**을 골라 한 번 실행하고, 본인 계정으로 필요한 구글 시트 접근 권한을 허용합니다. `Players`, `Runs` 시트와 서버 비밀값이 생성됩니다. 기존 기본 시트는 삭제하지 않습니다.
4. **배포 → 배포 관리 → 기존 웹 앱 선택 → 수정(연필) → 버전: 새 버전 → 배포**합니다. **새 배포를 별도로 만들지 마세요.**
5. 실행 주체는 **나**, 액세스 권한은 **모든 사용자**로 설정합니다. 구글 시트 자체는 공개하지 마세요.

게임에는 아래 주소가 정확히 들어 있습니다. 수정할 필요가 없습니다.

```text
https://script.google.com/macros/s/AKfycby9NXLZo8JTBnGRwRXjsIap9Zd29XpzEI96hG3D5Uj2fg079qFtcVBQKNGxVqRQzlKBWA/exec
```

위 주소를 브라우저에서 열면 `"game":"NEON RELAY"`, `"version":1`, `"ok":true`가 포함된 JSON이 표시됩니다. 이 상태 확인만으로 setup 실행이나 시트 쓰기까지 검증되는 것은 아닙니다. 게임에서 계정을 만들고 한 라운드를 테스트하세요.

## 2. GitHub에 업로드

압축을 풀고 아래 파일을 **저장소 최상위**에 배치합니다. 폴더 구조를 유지하세요.

| 파일 | 용도 | GitHub 업로드 |
|---|---|---|
| `index.html` | 엔진·CSS·게임 로직을 포함한 실행 파일 | 필수 |
| `assets/key-art.png` | 로비 배경 + 카카오톡 공유 이미지 | 필수 |
| `assets/favicon.svg` | 브라우저 탭 아이콘 | 필수 |
| `THIRD-PARTY-LICENSE.txt` | Three.js MIT 라이선스 | 함께 업로드 |
| `Code.gs` | 구글 시트 서버 코드 | Apps Script에 붙여넣기 |
| `publish-helper.html` | 카카오톡 이미지 주소 설정 도구 | 로컬에서 사용 |
| `source/` | 수정 가능한 분리 원본·빌드 도구·테스트 | 수정할 때만 필요 |
| `README.md`, `TEST-REPORT.md` | 배포 안내·테스트 범위 | 선택 |

GitHub 저장소 **Settings → Pages**에서 브랜치 기반 배포를 선택하고, 파일을 올린 브랜치와 `/ (root)`를 저장하세요. 활성화 후 표시되는 게임 주소를 사용합니다. 단순한 github.com 저장소 링크가 아니라 웹 페이지 주소입니다.

## 3. 카카오톡 미리보기 주소 완성

공유 이미지는 이미 포함되어 있습니다. 다만 제작 시점에는 실제 GitHub Pages 주소가 없으므로 `og:image`에 자리표시자가 있습니다.

1. PC에서 `publish-helper.html`을 엽니다.
2. 실제 GitHub Pages 게임 주소를 입력합니다.
3. 함께 받은 `index.html`을 선택합니다.
4. 다운로드한 HTML의 이름을 **index.html**로 맞추고 GitHub의 기존 파일을 교체합니다.

이미지 경로는 `https://실제게임주소/assets/key-art.png` 형태의 절대 주소로 자동 반영됩니다. 게임은 이 단계 전에도 실행되지만, 카카오톡 이미지 미리보기는 이 단계를 완료해야 합니다. 공유 서비스의 캐시 때문에 이전 미리보기가 당장 바뀌지 않을 수 있습니다.

## 4. 플레이 방법

- 최초 접속: PC / 모바일을 직접 선택합니다. 기종을 자동으로 탐색하지 않습니다.
- 모바일: 아이폰, 갤럭시 S·노트, 갤럭시 A·기타, 폴드·플립, 아이패드, 안드로이드 태블릿 중 선택합니다. 정확한 하드웨어 모델별 성능표를 적용하는 것은 아니며, 입력한 기기 유형과 현재 화면 크기에 맞춥니다.
- 아이폰: 보이는 화면 높이보다 8px 작게 만들고 하단에 맞춥니다. 안전 영역을 고려합니다.
- 아이폰 외: 기종 선택 완료 버튼을 누를 때 전체화면을 요청합니다. 브라우저가 거부하거나 지원하지 않으면 현재 화면에 맞춰 계속 진행합니다.
- PC: WASD / 방향키 이동, SPACE 대시, ESC 일시정지. 조준과 사격은 자동입니다.
- 모바일: 이동 스틱 + 대시 버튼. 설정에서 왼손 대시, 스틱 감도를 바꿀 수 있습니다.
- 빛나는 신호기 원 안에 총 12초 머무르면 복구됩니다. 원 밖으로 나가도 충전한 만큼은 유지됩니다.
- 드론을 정지시키고 결정을 모으면 레벨업합니다. 세 가지 성장 카드 중 하나를 선택합니다.
- 신호 복구 시 체력 25를 회복하고 주변 적에게 충격을 줍니다.
- 대시 중 짧은 무적 시간이 있습니다. 기본 재충전은 3.2초입니다.
- 5분에 최종 감시자가 등장합니다. 6분 안에 신호 3개 + 감시자 정지를 완료하면 성공입니다.
- 일시정지 화면에서 조기 종료하면 그 시점의 점수를 저장합니다.
- 친구와의 경쟁은 **공유 랭킹**입니다. 실시간 협동·대전은 구현하지 않았습니다.

## 5. 계정과 기록

한글 완성형 2~10자 아이디와 숫자 네 자리 PIN이 필요합니다. 첫 이용자는 로그인창에서 **새 아이디 만들기**를 선택합니다. 로그인 없이 출격하지 못하며, 서버도 인증되지 않은 기록 요청을 거부합니다.

`0516`은 숫자로 바꾸지 않고 문자열로 받아 처리합니다. 시트에 PIN 원문은 저장하지 않습니다. 사용자별 salt와 서버에만 저장한 비밀값으로 HMAC-SHA256 검증값을 만듭니다. 따라서 시트의 숫자 자동 변환으로 0이 사라지는 문제가 발생하지 않습니다. PIN을 조회해서 알려주는 방식은 지원하지 않습니다.

| Players 열 | 의미 |
|---|---|
| name | 한글 아이디 |
| salt / pinHash | PIN 검증용 값, 원문 PIN 아님 |
| createdAt / lastLogin | 등록·최근 로그인 시각, Unix 밀리초 |
| logins | 등록을 포함한 로그인 성공 횟수 |
| starts | 서버에서 승인한 라운드 시작 횟수 |
| playSeconds | 실제 플레이 중 누적 초 |
| bestScore / wins / xp | 최고 점수·성공 횟수·칭호 경험치 |
| failedPins / lockedUntil | PIN 실패 횟수·잠금 종료 시각 |
| tokenHash / expiresAt | 로그인 검증값·만료 시각 |
| sessionSeconds / sessionStartedAt / lastHeartbeat | 중복 없는 시간 합산을 위한 세션 기록 |

`Runs`에는 라운드 ID, 아이디, 시작·종료 시각, 점수, 시간, 처치 수, 신호 수, 성공 여부와 상태가 저장됩니다. 완료하지 않고 새 라운드를 시작한 기존 라운드는 abandoned로 표시됩니다. 단순히 창을 닫은 마지막 라운드는 active로 남을 수 있지만, 그 기록이 최고 점수나 성공 횟수에 반영되지는 않습니다.

- 시간은 **실제 게임 진행 중** 누적합니다. 로비·설정·일시정지·성장 선택·다른 탭에서는 늘어나지 않습니다.
- 60초가 모일 때마다 전송하고, 일시정지·결과·로그아웃 때 남은 초도 보냅니다. 시트에서 분이 필요하면 playSeconds를 60으로 나누세요.
- 같은 누적 시간이 두 번 도착해도 중복 가산하지 않습니다.
- 창을 닫을 때도 최종 전송을 시도합니다. 네트워크 단절·강제 종료 시 마지막 미확인 구간까지 100% 저장을 보장하지는 못합니다.
- 통신 실패를 최대 90초 동안 감지하면 일시정지합니다. 결과 저장 실패는 재시도 버튼을 제공합니다.
- 같은 계정으로 다른 기기에 로그인하면 기존 기기 세션은 무효화됩니다. 세션은 최대 12시간이며 PIN과 세션 토큰은 로컬 저장소에 저장하지 않습니다.
- 페이지를 새로고침하면 다시 로그인합니다. 진행 중 라운드는 이어지지 않고 완료된 계정 기록만 유지됩니다.
- 업그레이드는 라운드마다 초기화됩니다. 누적 XP는 칭호용이며 랭킹의 출발 능력치를 바꾸지 않습니다.
- 배경음·효과음·화질·흔들림·왼손 조작·스틱 감도는 해당 브라우저에 저장됩니다.

## 6. 운영자 작업과 한계

**PIN 분실:** Players 시트에서 해당 사용자의 행을 선택한 뒤, Apps Script에서 `resetSelectedPlayerPin`을 실행합니다. 시트에 나타나는 대화상자에 새 PIN 네 자리를 입력하면 검증값이 갱신되고 기존 로그인이 해제됩니다. 공개 API에는 PIN 초기화 기능이 없습니다.

**주의할 운영 범위:** 친구·소규모 그룹용입니다. 구글 시트 읽기·쓰기와 Apps Script 실행 한도 때문에 대규모 동시접속용으로 설계되지 않았습니다. 로그인 실패를 5회 반복하면 5분 잠급니다. 4자리 PIN은 강한 비밀번호를 대신하지 못하므로 실명·민감한 정보를 저장하지 마세요.

**랭킹 검증:** 서버가 점수 공식, 허용 범위, 경과 시간, 라운드 소유자와 중복 제출을 검사합니다. 게임 시뮬레이션 자체는 브라우저에서 실행되므로 클라이언트를 변조한 치트를 완전히 막을 수 없습니다. 상품이나 금전이 걸린 공식 경쟁용 검증 서버가 아닙니다.

**그래픽:** 로우 폴리 모델, 공유 geometry/material, 적·탄환·효과 수 상한, 자동 해상도 하향 조절을 적용했습니다. 실기기 GPU 성능 측정은 진행하지 못했으므로 프레임률을 보장하지 않습니다. 느린 기기에서는 배터리 절약 모드를 선택하세요.

**로그인 실패:** Code.gs 교체만 하고 기존 배포의 새 버전을 지정하지 않은 경우, setup 미실행, 모든 사용자 권한 미설정, 네트워크 차단 여부를 확인합니다. 게임은 연결 실패 시 임의의 게스트 모드로 전환하지 않습니다.

**수정:** `source/`의 HTML·CSS·JS를 편집하고 저장소 루트에서 `python3 source/build.py`를 실행하면 index.html이 다시 생성됩니다. 빌드는 기존 index.html에 설정한 og:image / og:url 주소를 유지합니다. 테스트 코드는 게임 HTML에 포함되지 않습니다.

## 7. 기술 근거

- Apps Script의 웹 앱은 doGet / doPost로 요청을 처리합니다. 이 프로젝트는 비밀값을 URL 쿼리에 노출하지 않도록 JSON 본문을 POST합니다. [Google 웹 앱 문서](https://developers.google.com/apps-script/guides/web)
- ContentService 응답은 googleusercontent.com으로 리다이렉트될 수 있습니다. 클라이언트가 리다이렉트를 따르도록 구성했습니다. [Google ContentService 문서](https://developers.google.com/apps-script/guides/content)
- Fullscreen API는 브라우저 지원과 권한에 영향을 받습니다. 지원되지 않는 경우 브라우저 뷰포트로 표시합니다. [MDN Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Fullscreen_API)

## 8. 에셋

Three.js 0.160.1 (MIT)을 HTML 안에 포함했습니다. 폰트 CDN, 분석 SDK, 광고, 외부 음악 다운로드는 없습니다. 배경음악과 효과음은 Web Audio 합성으로 재생합니다.

공유 이미지 `assets/key-art.png`는 이 프로젝트를 위해 이미지 생성 도구로 제작했습니다. 파비콘은 직접 작성한 SVG입니다. 키 아트는 분위기용 일러스트이며 실제 게임 화면과는 다릅니다. 이미지 생성 프롬프트는 `source/ART-PROMPT.txt`에 포함되어 있습니다.
